# Архив с файлами

В панели у завершённой партии, для которой ещё нет архива, включить
«Скачать PDF и фото в ZIP», затем подготовить ZIP/XML. Подготовка идёт
отдельным серверным процессом: закрытие страницы её не отменяет.
Ошибку подготовки видно в панели; повторный запуск не меняет исходные карточки.

CLI:

```powershell
python -m espbs --data-dir data export BATCH_ID --output data/exports --include-files
python -m espbs verify data/exports/BATCH_ID.zip --receipt receipt.json
```

Без флага сохраняется прежний формат v1, только ссылки. Уже опубликованный ZIP
не заменяется другим режимом: для архива с файлами нужна новая партия. Это
сохраняет ранее выданные контрольные суммы и подтверждения локальной копии.

## Формат v2

- `products.xml`: исходные записи без переписывания URL и без ложного изменения
  `attachments_downloaded`. Факт упаковки описывает индекс, а не исходная запись.
- `attachments.jsonl`: для каждой ссылки — record_id, вид материала, исходный
  URL, статус embedded/skipped/failed. У скачанного файла: путь в ZIP, SHA-256,
  размер, конечный URL, Content-Type. У пропуска/ошибки — причина.
- `files/<sha256>.<ext>`: одна копия каждого точного дубля внутри партии.
- `manifest.json`: версия 2, контрольные суммы XML и индекса, размеры,
  число записей индекса, сводка файлов/пропусков/ошибок.

Независимая verify проверяет XML, индекс, все вложения, отсутствие лишних и
повторяющихся ZIP-элементов, размер и SHA-256 каждого файла. ZIP не распаковывается.
Хеши подтверждают целостность, но не происхождение и не право использования.
Материал со страницы может относиться ко всей серии, а не только к модели.

## Границы первого режима

Скачиваются PDF и растровые JPEG/PNG/GIF/WebP. Проверяется сигнатура файла:
HTML-заглушка не становится PDF. Это не антивирусная проверка и не полная
валидация внутренней структуры документа. Office, ZIP, CAD, SVG и ссылки без
расширения PDF пока остаются ссылками с явной причиной пропуска.

До 50 различных адресов загрузки, 32 МиБ на файл, 256 МиБ уникальных файлов,
пять минут на сетевой этап партии; текущий запрос может завершиться позже
по сетевому тайм-ауту. Остальные ссылки записываются в отчёт. Счётчики считаются
по ссылкам, количество уникальных файлов отдельно. pHash и поиск похожих
изображений не реализованы; разрешение исходного изображения не изменяется.

Только публичный HTTPS. Проверяются robots.txt, DNS/IP, редиректы, общие
ограничения домена и Crawl-delay. Файл должен находиться на том же домене,
что и сохранённый источник материала. Для официального домена из справочника
также разрешены его поддомены, если ссылка присутствует в карточке. Ведущий
`www.` учитывается как вариант основного домена. Перенаправления между доменом
ссылки и исходной карточки проверяют robots.txt каждого домена отдельно.
Произвольные сторонние CDN не подключаются автоматически. Изображения Olnisa
запрещены. Ограничения источника не обходятся.

Данные обрабатываются потоково. Временный файл хранит не более одного материала,
индекс ограничен 256 МиБ; в памяти не собирается весь каталог.
Проверки свободного места сохраняют заданный резерв. Ошибка записи или нехватка
диска отменяет публикацию ZIP, но не удаляет карточки. При штатной ошибке временные
файлы закрываются; аварийное завершение может оставить `.partial` для отдельной
проверки оператором. Повтор запуска не удаляет чужие временные файлы.

Все долговременные бинарные файлы находятся внутри ZIP партии. Поэтому прежний
сценарий «скачать → проверить → подтвердить копию → отдельно подтвердить очистку»
освобождает и их место. Никаких автоматических удалений и фонового общего кэша нет.

Это формат ESPBS, не формат импорта Битрикс или OpenCart.
