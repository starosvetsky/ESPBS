# Передача комплекта ESPBS

Комплект добавляет инструкции разработки, не меняя код парсера, зависимости или сервер. Скиллы — адаптации под проект, а не полная установка внешних плагинов.

## Состав и использование

В `.agents/skills/` находятся пять скиллов: espbs-debugging, espbs-verification, espbs-testing, espbs-performance и espbs-data-integrity. Выбирай только относящиеся к текущей задаче. В `.codex/agents/` находятся espbs-python, espbs-qa и espbs-reviewer. Модель и reasoning не переопределены: используются настройки родительской задачи.

Открывай Codex в корне Git-репозитория, рядом с AGENTS.md. На этом компьютере это `D:\Codex\ESPBS\EnergoStorParser_v0.5\EnergoStorParser_v0.5`, а не внешняя папка `D:\Codex\ESPBS`.

Согласно документации Codex, проектные скиллы обнаруживаются в `.agents/skills`, роли — в `.codex/agents/*.toml`. В уже открытой задаче проверь доступность после нового сообщения; если каталог не обновился, открой новую сессию в корне проекта. Не объявляй роль загруженной без проверки. Если клиент не поддерживает эти роли, передай содержимое соответствующего TOML обычному субагенту; скиллы можно прочитать явно по пути. Глобальную конфигурацию менять не требуется.

## Разделение работы

Простую правку выполняй одним агентом. Для существенного изменения хранения, восстановления или экспорта делегируй независимую проверку QA либо reviewer, если инструменты субагентов доступны. Для большой задачи можно использовать обоих. Не занимай агента зависимой работой, пока отсутствует результат предыдущего этапа.

Координатор задаёт конкретный вопрос, область файлов и ожидаемый результат. По умолчанию код пишет один исполнитель; QA и reviewer исследуют без правок. Если QA пишет тесты, закрепи за ним отдельные файлы. Ревью финального diff выполняй после стабилизации реализации, затем проверь относящиеся к найденным ошибкам исправления. Координатор отвечает за итоговую интеграцию, проверки, commit и push. Ограничение «без правок» задаётся инструкцией, а не отдельной sandbox-политикой.

## Сообщение для соседней задачи

```text
В корне ESPBS подготовлен комплект docs/agent-kit/HANDOFF.md. Прочитай его и AGENTS.md. Проверь git status, получи origin и сопоставь актуальный верхний раздел docs/PLAN.md с кодом; сохрани текущую задачу и чужие изменения.
Используй подходящие проектные скиллы из .agents/skills. Для существенной правки хранения или экспорта делегируй независимую проверку espbs-qa либо espbs-reviewer; по умолчанию только основной исполнитель меняет код. Если именованные роли недоступны, прочитай .codex/agents/*.toml и передай нужные инструкции обычному субагенту. Не утверждай, что агент запускался, если инструментов нет.
Продолжай уже согласованный этап. Не мигрируй стек, не начинай новый массовый сбор и не меняй сервер из-за подключения комплекта. Результат подтверждай проверками на временных данных; commit и push выполняй по правилам проекта.
```

## Проверка комплекта

Структуру SKILL.md проверяют `quick_validate.py` из skill-creator; TOML — Python 3.12 `tomllib`. Это проверка формата и инструкций, не доказательство загрузки ролей клиентом или качества будущих изменений. Рабочее испытание — ближайшая реальная ограниченная задача с независимой проверкой результата.
