# Небольшие архивные части без повторного парсинга

У завершённого задания нажать «Создать следующую архивную часть». Появится
отдельная партия с исходными карточками. В ней можно подготовить ZIP с файлами,
скачать, проверить и отдельно подтвердить очистку. Кнопка возврата ведёт
к исходной партии, где доступна следующая часть и последние десять созданных.

В части не более 25 карточек и, как правило, не более 40 ссылок на материалы.
Граница выбирается между карточками. Если в одной карточке больше 40 ссылок,
она попадает в отдельную часть целиком: исходные поля не обрезаются. Ограничения
загрузчика по числу файлов, размеру и времени остаются; пропуски видны в отчёте.
Это распределение карточек, а не гарантия скачивания всех ссылок любой партии.

Оригинальные record_id, payload, content_sha256 и collected_at копируются
без изменений. Сеть для создания части не нужна. Исходная партия запечатывается,
чтобы новые изменения не сдвинули границы уже созданных частей. Старый ZIP
остаётся неизменным. Новая часть занимает дополнительное место до её очистки.

API: `POST /api/jobs/{id}/archive-part` с `{"after":""}` для первой части.
В GET исходного задания поле `archive_parts.next_cursor` содержит курсор
следующего запроса, `done` сообщает, что все карточки распределены, а не
что архивы всех частей уже скачаны. Один курсор возвращает ту же часть,
поэтому повтор HTTP-запроса не дублирует данные.

Если копирование прерывается, повторяется запрос того же курсора. Копия
записывается транзакционно, повтор не увеличивает счётчики. До завершения
снимка очистка родителя блокируется. Уже законченная часть независима от
родителя. Не очищать исходную партию, пока нужны ещё не созданные части.

После аварии в коротком промежутке между созданием пустого задания и его
регистрацией у родителя может остаться пустое задание PREPARING. Исходные
записи не теряются; автоматическое удаление таких заданий не выполняется.

Создание следующей части и очистка запускаются вручную. Автоматическая ротация
миллионного каталога и докачка отдельного оборванного бинарного файла по Range
пока не реализованы. Повтор подготовки ZIP заново скачивает материалы этой
маленькой части; успешно созданные ZIP предыдущих частей не переделываются.
