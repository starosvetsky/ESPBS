# Продолжение работы из дома

Состояние на 14 октября 2026 года. API и панель управления заданиями реализованы и проверены реальными ограниченными сборами через браузер.

## Что уже работает

- `espbs/storage.py`: отдельная SQLite-БД партии, сохранение каждой записи, повтор без дублей внутри партии.
- `espbs/archive.py`: ZIP/XML v1, манифест, контрольные суммы, независимая проверка архива.
- `espbs/eltex.py`: ограниченный сбор официального раздела Ethernet-коммутаторов Eltex, характеристики, ссылки на документы, происхождение данных и причины проверки качества.
- `espbs/jobs.py`: очередь на диске, состояния, остановка/продолжение, последние 1000 событий, блокировка второго рабочего процесса и экспорта активной партии.
- CLI: `collect`, `runs`, `run-status`, `stop`, `resume`, `events`, команды партий и архивов. Подробности — [COLLECTION.md](COLLECTION.md).

В предыдущем шаге прошли 24 теста локально и CI на Windows/Linux. Выполнен реальный сбор MES1428 и MES2300-08: остановка после первой карточки, продолжение со второй, проверка ZIP/XML на две записи. Реальные данные остались на рабочем компьютере в игнорируемых каталогах и через GitHub не передаются.

## Следующий шаг: управление заданиями через интерфейс

Локальная реализация этого шага находится в `espbs/api.py` и `espbs/web/`. Она
показывает задания, товары и события, запускает отдельный worker-процесс и
восстанавливает состояние из SQLite. Следующая сессия должна проверить её на
реальном небольшом сборе. Следующая сессия должна подготовить безопасный серверный доступ.

Проверены задания 2/2 и 5/5. Во втором сценарии сбор остановлен после обнаружения
пяти URL, затем продолжен из интерфейса и завершён с пятью сохранёнными товарами.
Панель показала фактические карточки и события. Длинные URL корректно переносятся,
а узкое окно переключается на одноколоночную компоновку.

Цель: пользователь открывает панель, запускает небольшой сбор Eltex, видит фактические записи и журнал, останавливает задание и продолжает его после перезапуска приложения. Сбор должен жить в серверном процессе и не зависеть от открытого окна клиента.

### Порядок реализации

1. Прочитать `AGENTS.md`, [PLAN.md](PLAN.md), [UX_FLOW.md](UX_FLOW.md), [COLLECTION.md](COLLECTION.md) и текущий код. Сохранить существующие CLI-команды и формат архивов.
2. Добавить API поверх `Job` и `Batch`: список и состояние заданий, создание ограниченного сбора, остановка, продолжение, журнал с курсором, постраничное чтение сохранённых товаров. Длительный сбор выполнять отдельным рабочим процессом; HTTP-запрос запуска должен быстро возвращать ID задания.
3. Обработать жизненный цикл рабочего процесса: повторный запуск, аварийный выход, устаревшее RUNNING, перезапуск API. Существующая файловая блокировка остаётся защитой от двух исполнителей. Не считать RUNNING в БД доказательством живого процесса.
4. Подключить панель к API. Взять визуальное направление существующей страницы `index.html` / `styles.css`, свериться с UX Flow. Показать источник, лимит, состояние, найдено/сохранено, качество, ошибку и журнал. Процент считать только при известном знаменателе и объяснять, что лимит задания — не размер каталога.
5. Добавить запуск, остановку и продолжение с понятными состояниями кнопок. При потере связи показывать отсутствие соединения и после восстановления загружать фактическое состояние. Не подставлять демонстрационные числа вместо серверных данных.
6. Для первой локальной проверки API слушает loopback. Перед доступом с другого компьютера предусмотреть аутентификацию и защищённое соединение. Не публиковать управляющий API или секреты через GitHub Pages; Pages остаётся статической страницей проекта. Произвольная командная строка на сервере в этот шаг не входит, достаточно журнала парсера.
7. Выполнить проверки ниже, обновить документацию с командами запуска, сделать отдельный коммит и push. Пользователь уже разрешил отправлять каждый проверенный шаг на GitHub.

### Критерии готовности

- Из интерфейса запускается ограниченное задание Eltex, отображаются настоящие события и сохранённые карточки.
- Остановка и продолжение работают; повторные клики не создают двух исполнителей одного задания.
- Закрытие окна клиента не прерывает серверный сбор. После перезапуска клиента состояние восстанавливается.
- Ошибка источника и аварийный выход рабочего процесса видны пользователю; уже сохранённые записи остаются доступны.
- Проверены перезапуск API и восстановление после обрыва соединения. Журнал не теряет новые события из-за неверного курсора и не загружается целиком при каждом опросе.
- Существующие 24 теста проходят, добавлены тесты API и жизненного цикла заданий. Обычные тесты не обращаются к реальным сайтам. Отдельно выполнен небольшой реальный сбор и проверен интерфейс в браузере.
- Документация различает локальную проверку, CI и фактическое развёртывание на Selectel.

## Ограничения, которые нужно сохранить

Парсер предназначен для Selectel с ограниченным диском. Пользователь вручную скачивает ZIP/XML на домашний компьютер, проверяет архив и отдельно подтверждает освобождение серверного места. Компьютер не должен постоянно работать ради сбора. Нельзя автоматически удалять данные после экспорта или HTTP-скачивания.

Защита по свободному месту и подтверждённая очистка ещё не реализованы: их необходимо сделать перед длительной эксплуатацией на сервере. Пока использовать только небольшие ограниченные задания. Вложения представлены ссылками; OpenCart-импорт и desktop-упаковка будут отдельными этапами.

Старый `app.py` — неполный Tkinter-прототип. Не создавать фиктивные адаптеры ради запуска его импортов. Новый рабочий путь — пакет `espbs`.

Развёртывания на Selectel не было: прежняя попытка SSH завершилась `Permission denied (publickey)`. Доступ из дома нужно проверять заново, если потребуется развёртывание. Локальный успех не подтверждает работу на сервере.

## Как продолжить на другом компьютере

В существующей копии сначала проверить `git status`, сохранить свои незакоммиченные изменения, затем получить `main` без перезаписи чужой работы:

```shell
git switch main
git pull --ff-only origin main
python -m venv .venv
```

На Windows из корня репозитория:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-parser.txt
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Если копии ещё нет: `git clone https://github.com/starosvetsky/ESPBS.git`, затем перейти в `ESPBS`. Локальный путь может отличаться от рабочего `Q:\repo\NRGSRTR`.

Сообщение для начала следующей сессии:

> Продолжаем ESPBS. Прочитай AGENTS.md, docs/API.md и docs/NEXT_STEP.md. Проверь локальную панель реальным ограниченным заданием Eltex в браузере, исправь найденное, затем подготовь аутентификацию и TLS для будущего развёртывания на Selectel. Не открывай управляющий API наружу без защиты. Сохрани сценарий Selectel → ручное скачивание ZIP/XML → отдельное подтверждение очистки.
