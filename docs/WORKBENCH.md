# Сбор по ссылке и справочник производителей

**Обновление:** текущий упрощённый интерфейс и исправление полного обхода описаны
в [SIMPLE_COLLECTION.md](SIMPLE_COLLECTION.md). Ниже — предыдущий этап с ручными настройками.

Реализовано 15 октября 2026 года.

Установлено и проверено на Selectel: [DEPLOYMENT.md](DEPLOYMENT.md).

## Сценарий

1. Вставить HTTPS-ссылку магазина, категории или товара.
2. Нажать «Пробный разбор»: проверяются исходная страница и до трёх карточек.
   Образцы показывают реальные извлечённые поля, а не сгенерированные данные.
3. Проверить бренд и точный MPN. При необходимости задать правила CSS в разделе
   «Правила для нового сайта» и сохранить их для домена.
4. Задать лимит до 1 000 000 товаров. Выбор «После сбора дополнить
   данными производителей» создаёт отдельное задание после окончания сбора.
5. Перейти в обогащённую партию, посмотреть результаты и скачать её ZIP/XML.
   В исходной партии также остаются предложения магазина.
6. После изменения справочника нажать «Дополнить данными производителей» у
   завершённой партии: новый результат создаётся без повторного сбора магазина.

## Новый сайт

Универсальный адаптер читает однозначный Product JSON-LD и списки Product с URL.
Для другой HTML-структуры доступны CSS-поля name, manufacturer, mpn, description,
price, availability, product_links, next_links. Значение берётся из content либо
текста элемента; ссылки — из href. Правила хранятся для домена и фиксируются
в конфигурации каждого задания. Пример для синтетического сайта:

```json
{"name":"h1","manufacturer":".brand","mpn":".article","product_links":"a.product","next_links":"a.next"}
```

Отсутствие JSON-LD и правил — видимая ошибка распознавания. JavaScript страницы
не исполняется; капчи и ограничения не обходятся. Домашняя страница сайта сама
по себе не гарантирует обнаружение всех товаров. Пагинация требует next_links;
не более 100 000 страниц за задание и 10 000 ссылок со страницы.

Готовый адаптер Olnisa поддерживает разделы /manufacturers/бренд/ и карточки,
не только Eltex. Его пагинация с query запрещена robots.txt и не запрашивается.
Другие разделы Olnisa проходят общий разбор; изображения Olnisa исключаются.

## Производители

Справочник хранится в directory.sqlite3 в каталоге данных, вне Git. В панели
можно добавить/изменить бренд, официальный HTTPS-сайт, необязательный шаблон
URL карточки с одним {mpn} и CSS-правила официальных полей.
Отдельная форма сохраняет связь бренд + MPN → URL официальной карточки.
Связь является кандидатом, а не подтверждением совпадения: при получении
проверяются бренд и точный MPN самой страницы. Регистр и крайние пробелы
нормализуются; суффиксы, дефисы и внутренние пробелы не удаляются.
Четыре ранее проверенных алиаса Eltex сохранены как совместимый первый набор.

Просто указать главную страницу производителя недостаточно для поиска любой
модели: нужны шаблон URL или сохранённая ссылка на карточку. Автоматического
веб-поиска официальных сайтов и обхода полного каталога производителя пока нет.
Если производитель не публикует MPN, нужны правила его извлечения либо отдельный
проверенный адаптер; сопоставление по похожему названию не применяется.

## Отдельная очередь и результат

Новая партия хранит исходные записи в собственной очереди inputs; исходный
магазин при обогащении не запрашивается. До 100 записей копируются сразу,
большая очередь подготавливается worker-ом порциями по 100 с checkpoint.
Очистка родителя заблокирована до завершения копирования; после этого
родительскую партию можно очистить без нарушения работы очереди.
Новая версия также хранит original_record для повторного
обогащения. Остановка, продолжение, контроль диска и архивирование работают
через общий механизм заданий. Очистка обогащённой партии по отдельному действию
удаляет также её inputs, сохраняя метаданные и журнал.

Результаты: MATCHED, NO_MANUFACTURER, NEEDS_MAPPING, MISSING_IDENTITY,
MISMATCH, ERROR. Панель показывает число карточек каждого состояния.
Предложения магазинов не заменяются официальными ценами. Происхождение
официальных полей и время получения сохраняются. Успешные официальные карточки
кэшируются на 24 часа по бренду/MPN; изменение URL или правил обновляет кэш.
Кэш — общий справочник: очистка партии не удаляет его.

Фото универсального официального источника читаются из JSON-LD и допускаются
только с того же домена. CDN на другом домене пока не подключены. Вложения
остаются ссылками, формат архива — references-only. Универсальное извлечение
произвольных PDF-ссылок пока не реализовано; адаптер Eltex сохраняет документы.

## Сеть и проверки

Для произвольных адресов разрешён HTTPS/443 без авторизации в URL. Перед
соединением DNS проверяется на публичные IP, выбранный IP закрепляется для
соединения с проверкой TLS исходного имени. Междоменные запросы и редиректы
отклоняются. robots.txt соблюдается, интервал минимум 2 секунды (либо crawl-delay),
ответ до 6 MiB. Ошибки роботов и HTTP видны пользователю.

55 автоматических тестов: разные бренды, точный MPN и несовпадения, кэш,
перезапуск очереди после очистки родителя, очистка inputs, API, правила CSS,
публичные адреса и запреты robots. Реально через локальную панель проверены
пробный разбор Olnisa MES2428, сбор и отдельное автоматическое обогащение
с фото. Универсальный JSON-LD проверен на реальной странице Eltex; отсутствие
MPN корректно отмечено. Другие бренды проверены синтетическими данными,
не заявлены как проверенные реальные интеграции.

## Большие задания

100 больше не является пределом сбора. API и панель принимают до 1 000 000.
Это максимальное желаемое число, а не обещание обнаружить столько товаров:
при исчерпании доступных страниц задание завершится с фактическим количеством.
Обнаружение и загрузка чередуются с очередью около 500 ссылок; целая страница
может временно увеличить её. Счётчики и индексы очереди не требуют полного
пересчёта товаров на каждом сохранении. В браузер поступает 50 карточек за раз.

Полный запуск на миллион товаров не проводился. Проверены принятие лимита
1 000 000, реальная обработка 105 синтетических записей на 21 странице и
остановка/продолжение фонового снимка 101 записи. Ограничения остаются реальными:
скорость источника (при 2 сек/карточку миллион — минимум около 23 суток без
учёта прочих запросов), свободное место, доступность пагинации и формат экспорта.
Текущий XML ограничен 8 GiB; очень большой результат может потребовать будущего
разбиения на архивы. Автоматического разбиения одного задания на несколько
партий пока нет. Контроль диска приостанавливает работу заранее, но не
резервирует место под будущий архив. Архивирование незавершённого задания
пока не разрешено; при паузе по месту нужно освободить другие проверенные
партии или увеличить диск, затем продолжить.
