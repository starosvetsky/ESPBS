# История заданий

Панель показывает по 25 заданий. «Дальше» открывает более старые,
«Назад» возвращает предыдущую страницу, «К новым» — первую.
Выбранное задание остаётся открытым при смене страницы истории.

Список не читает ZIP, отчёты вложений и состояние архивных очередей.
Подробности выбранного задания загружаются отдельно. Индекс
`job-index.sqlite3` содержит только ID и неизменную дату создания;
прогресс читается из БД заданий текущей страницы.

Новые задания регистрируются при создании, в том числе из CLI и фоновых
процессов. При запуске API отсутствующие записи восстанавливаются по
каталогу jobs. Это также закрывает обрыв между созданием БД и регистрацией.
Индекс можно восстановить из исходных БД; сами товары в него не копируются.
При ручном переносе старых БД нужно перезапустить API.

Курсор не зависит от времени изменения файлов. Новые задания не сдвигают
уже просмотренные страницы: чтобы увидеть их, вернитесь к новым.
При одинаковой дате порядок определяется ID. Общий размер истории не
подсчитывается при каждом запросе.

Ограничение: запуск API ещё перечисляет все файлы заданий для восстановления
индекса. Остальные разделы (склад, сводка диска) требуют отдельной проверки
масштабирования. Эта доработка не доказывает готовность миллиона товаров.
