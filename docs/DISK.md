# Контроль свободного места

Реализовано 15 октября 2026 года, проверено локально. Этот шаг ещё не развёрнут на Selectel.

По умолчанию ESPBS оставляет 1024 МиБ свободного места. Для сбора дополнительно нужны 256 МиБ: это запас для небольших текущих партий и операций SQLite, а не гарантированное место для архива любого размера. Порог задаётся переменной окружения `ESPBS_DISK_RESERVE_MIB` (целое число не меньше 64). API и worker должны получать одинаковое окружение; дочерний процесс наследует его от API.

Место проверяется до создания задания, перед запросами страниц и перед сохранением результатов. При снижении ниже порога задание переходит в `PAUSED_DISK`, сохраняет очередь и причину остановки. После освобождения места пользователь нажимает «Продолжить». Автоматического удаления и автоматического возобновления нет.

Панель показывает свободное место на диске данных, резерв и размеры файлов партий, заданий и архивов. Состояние обновляется каждые 5 секунд через `GET /api/storage`. Размеры включают служебные файлы SQLite и временные файлы в соответствующих каталогах; это размеры файлов, не фактически занятые блоки файловой системы. Другие каталоги в эти суммы не входят.

Перед созданием нового архива XML потоково просчитывается без накопления в памяти. На диске назначения требуются резерв + размер XML + 1% + 16 МиБ на упаковку. При отказе на этой проверке открытая партия не запечатывается. Во время упаковки свободное место проверяется снова. Уже готовый архив можно повторно получить при низком свободном месте без создания новой копии.

Проверки места являются предупредительными: другой процесс или параллельный сбор может занять диск между проверкой и записью. Это не файловая квота и не резервирование блоков. Внезапная ошибка записи не удаляет исходную партию; при полном диске запись статуса также может оказаться невозможной. После восстановления места состояние и журнал нужно проверить. Контроль не распространяется на ручной JSONL-импорт через `ingest`.

Проверено 34 тестами: отказ нового задания без создания данных, пауза после первой записи, продолжение без потери записей, отказ экспорта до запечатывания, ошибка при упаковке и API состояния диска. Визуальная проверка новой строки панели в браузере пока не выполнена.

Следующий шаг: проверка скачанного архива на компьютере и отдельное подтверждение очистки соответствующей серверной партии. Скачивание само по себе не должно разрешать удаление.
