# Первый реальный источник: Eltex

Реализован ограниченный сбор официального раздела [Ethernet-коммутаторы MES](https://eltex.ru/catalog/ethernet-kommutatory-mes/). Старый домен eltex-co.ru перенаправляет на eltex.ru. Это серверная команда; новый GUI и развёртывание на Selectel ещё не выполнены.

## Запуск

Python 3.12+. Из корня репозитория:

```shell
python -m pip install -r requirements-parser.txt
python -m espbs collect eltex --limit 3
python -m espbs runs
python -m espbs run-status JOB_ID
python -m espbs stop JOB_ID
python -m espbs resume JOB_ID
python -m espbs events JOB_ID
python -m espbs export JOB_ID --output exports
python -m espbs verify exports/JOB_ID.zip
```

`JOB_ID` выдаётся первым событием запуска; он совпадает с ID партии. `stop` выполняется в другом терминале и запрашивает остановку. Также поддерживается Ctrl+C; SIGTERM запрашивает остановку. Команда работает в текущем процессе, фоновый сервис пока не устанавливается. `--data-dir PATH` перед подкомандой выбирает каталог данных. На всех командах одного задания нужен тот же каталог.

События поступают JSON-строками в stderr; итоговый JSON — в stdout. Ошибка задания возвращает код 1. Состояния: READY, RUNNING, STOPPED, COMPLETED, FAILED. Статус показывает целевой лимит, найденные и сохранённые карточки, оценки качества и ошибку. Лимит — от 1 до 100 карточек, по умолчанию 3. Он означает максимум, а не размер всего каталога. Обход ограничен 20 страницами.

Очередь, checkpoint и последние 1000 событий сохраняются в `data/jobs/`. Товары — в отдельной БД партии. После аварийного завершения статус может остаться RUNNING; `resume` получает системную блокировку и продолжает очередь. Второй одновременно работающий процесс отклоняется. Если авария произошла между сохранением товара и checkpoint, карточка запрашивается повторно, но новая строка товара не создаётся. Счётчик completed относится к подтверждённым checkpoint, а не числу HTTP-запросов.

Экспорт работающей партии запрещён. Остановленную неполную партию можно экспортировать; после этого она запечатана и продолжить её сбор нельзя — потребуется новое задание. Исходные данные не удаляются.

## Данные и ограничения

- Название, бренд, описание и характеристики извлекаются из Product JSON-LD. Повторяющиеся названия характеристик сохраняются списками. Исходный JSON-LD, хлебные крошки, заголовок страницы и хеш HTML сохраняются как происхождение данных. Полный HTML не архивируется.
- Документы сохраняются ссылками из раздела загрузок производителя; содержимое PDF и изображения не скачиваются. Исходный JSON-LD может содержать ссылку на изображение.
- Явный MPN сохраняется только при наличии в исходных данных. Название модели не подставляется вместо артикула. REVIEW перечисляет причины проверки; GOOD означает лишь прохождение этих первичных проверок, не экспертную оценку товара.
- Перед сбором читается robots.txt. Неудачное получение останавливает задание. Wildcard-запреты применяются консервативно, даже если находятся в группе другого робота; это может дополнительно ограничить сбор. Перенаправления отклоняются для ручной проверки.
- Между началами HTTP-запросов минимум 2 секунды. Таймауты подключения/чтения — 5/20 секунд, ответ ограничен 6 MiB. Ошибки HTTP, включая 403 и 429, завершают задание с сохранением очереди. Автоматических повторов нет; при ограничении источником нужно выдержать указанный им срок до ручного продолжения. Обход блокировок не реализован.
- Защита по свободному месту и очистка пока относятся к следующему этапу. Не запускать бесконтрольный сбор на ограниченном диске. Каждый новый запуск создаёт новую партию; межпартийной дедупликации нет.

## Проверка 14 октября 2026

На Windows выполнен реальный сбор двух карточек: MES1428 (21 характеристика) и MES2300-08 (31). После первой записи задание остановлено, повторный запуск сохранил вторую. Обе получили REVIEW из-за отсутствующего явного MPN. ZIP/XML проверен независимо, содержит 2 записи. Реальные БД, архив и исследовательский HTML исключены из Git.

Обычные unit-тесты работают с явно синтетическим HTML, без сети. Проверяют извлечение, область ссылок, остановку/продолжение, повтор после сбоя между записью и checkpoint, блокировку второго процесса и экспорта, лимиты HTTP/robots и сохранение очереди при ошибках. Это не подтверждает запуск на Selectel.

Итог локальной проверки: 24 теста прошли (Windows, Python 3.13.6).
