# Управляемая очередь архивных частей

В завершённой исходной партии нажать «Готовить части автоматически
(до двух вперёд)». Очередь работает отдельным серверным процессом, поэтому
вкладку и компьютер можно закрыть. Она не выполняет повторный парсинг:
использует сохранённые карточки и скачивает материалы по сохранённым ссылкам.

## Ограничение накопления

Очередь обрабатывает части последовательно, максимум две неочищенные части
вперёд. Затем WAITING_DOWNLOAD: скачать ZIP, проверить обновлённой verify,
подтвердить локальную копию и отдельно очистить часть. Очистку выполнять
в порядке частей. После этого вручную продолжить очередь.

Никаких автоматических подтверждений скачивания и удалений нет. Подтверждение
копии без очистки не освобождает место и не увеличивает окно. Если частей
больше нет, очередь завершается независимо от наличия последних ZIP на сервере.

Перед созданием/упаковкой части проверяется свободное место: установленный
резерв плюс 512 МиБ. При нехватке — PAUSED_DISK, после освобождения места
нужно продолжить вручную. Проверки места внутри упаковщика остаются включены.
Лимиты файла/архива/времени описаны в [ATTACHMENTS.md](ATTACHMENTS.md).

## Состояния

- QUEUED/RUNNING — процесс запущен или готовит части.
- WAITING_DOWNLOAD — достигнуто окно из двух частей, нужны скачивание и очистка.
- PAUSED_DISK — мало места; сохранённые данные не удаляются.
- REVIEW — архив опубликован, но есть skipped/failed. Проверить отчёт.
  Продолжение перейдёт к следующей части, не заменяя неполный ZIP.
- STOPPED — остановка по запросу после текущей части.
- FAILED — ошибка или исчезновение процесса; можно повторить запуск.
- COMPLETED — все части обработаны или ранее явно очищены пользователем.
  Это не гарантия полной документации; число неполных частей показано отдельно.

Номер обработанной части и текущая часть сохраняются в SQLite родителя.
Повтор после сбоя использует ту же часть. Если ZIP уже опубликован, проверяет
его, а не скачивает заново. Если ZIP не был опубликован, упаковка этой части
повторяется; побайтовая докачка отдельного файла не реализована.

Кнопка остановки завершает текущую часть, не обрывает файл посередине.
SIGTERM запрашивает такую же остановку; принудительное завершение процесса
восстанавливается через FAILED и повторный запуск. Исходную партию нельзя
очистить во время QUEUED/RUNNING. После остановки явная очистка родителя
по проверенному исходному архиву возможна, но продолжить очередь без
исходных записей уже нельзя.

Старый ZIP только со ссылками не перезаписывается. Если он встречен как
архив части, очередь останавливается с объяснением. Готовые части можно
проверять и очищать обычным способом независимо от очереди.

## API

- POST `/api/jobs/{id}/archive-queue-start` с `{}` — запустить/продолжить, 202.
- POST `/api/jobs/{id}/archive-queue-stop` с `{}` — запросить остановку, 202.
- GET `/api/jobs/{id}`: `archive_queue` содержит state, stop, last_seq,
  release_seq, current_child, incomplete_parts, pending, window и error.
  pending — последний сохранённый счётчик; обновляется при работе/продолжении.

Повтор запуска работающей очереди не создаёт второй процесс. У каждой исходной
партии своё окно; вручную созданные пользователем части и другие очереди
не входят в общий глобальный лимит. Общий резерв диска проверяется всеми.

миллионного сбора, постраничный список огромного числа заданий и импорт
в магазин остаются отдельными задачами; нагрузочный тест миллиона не проводился.
