# Локальная панель и API

## Запуск

Из корня репозитория после установки `requirements-parser.txt`:

```powershell
python -m espbs --data-dir data serve
```

Панель откроется на `http://127.0.0.1:8765`. Другой порт задаётся через
`--port`. Привязка к внешнему адресу намеренно отклоняется: до доступа с другого
компьютера нужны аутентификация и TLS. GitHub Pages не содержит API и остаётся
статической страницей проекта.

## Маршруты

- `GET /api/jobs` — список сохранённых заданий.
- `POST /api/jobs` с `{"source":"eltex","limit":3}` — создать ограниченное
  задание и запустить отдельный worker-процесс.
- `GET /api/jobs/{id}` — состояние и фактические счётчики.
- `POST /api/jobs/{id}/stop` и `/resume` — запросить остановку или продолжить.
- `GET /api/jobs/{id}/events?after=0&limit=100` — журнал с числовым курсором.
- `GET /api/jobs/{id}/products?after=&limit=50` — сохранённые товары с курсором.

Ответ запуска не ждёт окончания сбора. Закрытие вкладки не останавливает worker.
Файловая блокировка не допускает двух исполнителей одного задания. После
перезапуска API состояние загружается из SQLite; если `RUNNING` остался без
владельца блокировки, он становится `FAILED`, а уже сохранённые товары остаются.

## Проверка

```powershell
python -m unittest discover -s tests -v
```

На Windows локально прошли 28 тестов. Тесты API используют временные базы и
синтетические записи, не обращаются к Eltex и не доказывают развёртывание на
Selectel. Реальную проверку выполнять только с небольшим лимитом.
