## Обновление

Код сначала проверяется локально и отправляется в GitHub. На сервер передаются
только пакет `espbs` и `requirements-parser.txt`; `.git`, виртуальные окружения,
локальные базы и архивы не копируются. После обновления зависимостей:

```bash
/opt/espbs/.venv/bin/python -m pip install -r /opt/espbs/requirements-parser.txt
systemctl restart espbs.service
```

Развёртывание панели не означает готовность полного цикла архивов. Защита диска,
подтверждённое скачивание и отдельная очистка партий остаются этапом 4.

## Тестовая витрина

Каталог `catalog-demo/` — статическая страница для визуальной проверки конкретной
XML-выгрузки. `tools/build_catalog_page.py` сверяет размер, SHA-256, batch ID и
число записей с манифестом, затем создаёт безопасный `data.json`. На сервере
страница размещается отдельной папкой `/var/www/starosvetsky.ru/parser-results`;
корневые файлы портфолио при публикации не меняются.
