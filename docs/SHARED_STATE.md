# Общие ограничения и каталог

Локальная реализация, 17 октября 2026. Развёртывание на сервере отдельно.

Все штатные HTTP-клиенты заданий, обогащения и пробного разбора используют
общий каталог `data/traffic`. На hostname допускается один активный запрос;
между началами минимум две секунды, либо больший Crawl-delay клиента.
Дополнительно выдерживается такой же интервал после завершения ответа,
чтобы медленное соединение не сокращало паузу перед следующим запросом.
Блокировка действует между процессами, освобождается ОС при аварии.
Это ограничитель с ожиданием, не FIFO-очередь с гарантией справедливости.
Несколько установок с разными data-dir не координируются.

HTTP 403 блокирует дальнейшие запросы домена бессрочно. HTTP 429 сохраняет
Retry-After (число секунд или HTTP-дата), при отсутствии корректного заголовка —
паузу на час. Текущее задание завершается FAILED с понятной причиной;
возобновление после 429 ручное, повторный запуск до срока запрос не отправляет.
Ошибки ограничений при обогащении также останавливают задание.
Автоматического снятия 403 и обхода ограничений нет.
robots.txt проверяется клиентами; запрет конкретного пути останавливает задание,
не блокируя остальные разрешённые пути домена. Robots не определяет права
перепубликации материалов. Проверка условий использования сайта не автоматизирована.

`catalog.sqlite3` хранит последнюю запись по идентификатору source + external_id
(либо source_url). ID совпадает с ID записи партии и стабилен между заданиями.
Повторные сборы обновляют запись; разные источники пока НЕ объединяются, даже
при одинаковом MPN. Полный payload сохраняет исходные поля и предложение магазина.
Старые партии остаются снимками, существующие партии автоматически не мигрируются.
После сбоя между записью партии и каталога повтор задания восстанавливает каталог
до подтверждения checkpoint. При параллельных заданиях побеждает последняя запись.

Очистка подтверждённой партии освобождает принадлежащий ей последний payload
каталога, сохраняя идентификатор. Более новая запись из другой партии не удаляется.
Каталог занимает дополнительное место; размер включён в контроль хранилища.
Скачивание файлов, дедупликация по SHA-256/pHash и импорт Bitrix этим шагом
не реализованы. Каталог пока доступен через CLI/API, без нового экрана панели.

```powershell
python -m espbs --data-dir data catalog --limit 50
python -m espbs --data-dir data catalog --after RECORD_ID
python -m espbs --data-dir data traffic
```

API: `GET /api/catalog?after=ID&limit=50`, `GET /api/traffic`.
`payload: null` означает, что содержимое удалено при подтверждённой очистке.
Следующую страницу запрашивать по последнему ID; пустая страница завершает обход.

Проверки: полный набор на этапе внедрения — 73 теста; после финальных изменений
отдельно пройдены 6 тестов общих состояний и 9 тестов API. Проверены отдельные
процессы, оба HTTP-клиента, HTTP 403/429, Retry-After, остановка ожидания,
восстановление после сбоя, повторный сбор, пагинация и сохранение свежего payload
при очистке старой партии. Все данные синтетические; нагрузка миллиона товаров
и работа новой версии на Selectel не проверялись.
