# Проверка результата ESPBS

Для изменённого поведения выбери проверку, которая действительно обнаруживает его нарушение. Запусти её на текущем состоянии файлов, прочитай результат и код выхода. Результат субагента проверь по diff и его свидетельствам; не приравнивай «тест написан» к «тест проходит».

Из корня проекта на Windows используй существующий Python, предпочтительно .\.venv\Scripts\python.exe. Полный набор: `python -m unittest discover -s tests -v`. Для узкой проверки допустим discover с `-p test_<module>.py`; учитывай импорты соседних тестов. Не устанавливай другой тестовый стек без необходимости.

Выбирай объём по изменению: инструкции — проверка структуры и ссылок; адаптер — фикстуры и ограниченная реальная сверка, если она входит в задачу; хранение/экспорт — регрессии и связанные тесты восстановления; UI — доступная браузерная проверка. Не запускай реальные сборы, очистку или серверные операции ради формального чеклиста.

Для архива различай создание, независимую проверку, скачанную копию и разрешение очистки. Для развёртывания нужны свидетельства с сервера: локальный успех недостаточен. Не заявляй работу на миллионе записей без измерения.

Перед коммитом проверь diff, отсутствие чужих файлов и секретов. Следуй правилам Git из AGENTS.md; коммит и push выполняет основной агент. В результате назови проверку, исход и существенные ограничения. Повторяй её после новых влияющих изменений, а не без причины.
