# Тестирование ESPBS

Используй текущие unittest, unittest.mock и tempfile; сначала прочитай соседние тесты. Не мигрируй на pytest ради примеров из внешнего скилла. Обычный прогон должен быть воспроизводимым и не обращаться к сайтам или рабочему data/.

Выбирай сценарии по изменённому пути:
- Источник: реальная структура сохранённого HTML, пагинация, относительные ссылки, отсутствующие поля, 429/Retry-After и ответ блокировки. Синтетические данные помечай явно; они не доказывают поддержку сайта.
- Хранение: повтор операции, конкурирующий запуск, остановка между фиксацией состояния и созданием файла. Проверяй сохранённые записи и возможность продолжения после повторного открытия БД.
- Части: неизменный диапазон версий, повтор регистрации с тем же ID, обновление одного товара несколько раз, восстановление .pending, отсутствие потерь и лишних версий на границах диапазона.
- Архив: проверка без исходной БД, повреждённый файл или манифест, прерванная упаковка, повтор экспорта, нехватка места.
- Очистка: скачивание/HTTP-ответ сами по себе не дают разрешение; подтверждение относится к конкретной проверенной копии и партии. Проверяй только временные данные.

Для сбоя процесса используй изолированный subprocess, когда mock исключения не воспроизводит аварийное завершение. Для времени и HTTP предпочитай управляемые зависимости вместо sleep и живой сети. Проверяй контракт и содержимое результата, а не только то, что mock был вызван.

Не вводи произвольный процент покрытия как критерий готовности. Сообщай выявленный пробел и проверяемый инвариант. Не расширяй тестирование на несвязанные компоненты без причины.
