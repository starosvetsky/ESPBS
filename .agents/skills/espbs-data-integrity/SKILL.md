# Сохранность данных ESPBS

Корневой AGENTS.md определяет ограничения продукта. Прочитай только относящиеся к задаче документы STREAMING.md, ARCHIVES.md, RETENTION.md, SHARED_STATE.md и актуальный верхний раздел PLAN.md. Документация содержит историю; фактическую реализацию проверяй в коде.

Перед изменением опиши переход состояния: что уже зафиксировано, что ещё создаётся, как повтор операции узнаёт ранее начатую работу. Для нескольких SQLite-БД и файлов не предполагай общую атомарную транзакцию: определи восстановление на каждой границе.

Для потоковых частей проверь:
- ID и диапазон резервируются до создания дочерних файлов; повтор завершает ту же операцию.
- Курсор версий монотонен; хеш record_id не заменяет порядок поступления.
- Части сохраняют снимок выбранных версий при дальнейшем обновлении родителя; сбор не требует запечатывания родителя.
- Экспорт несёт проверяемое происхождение и диапазон; независимый проверяющий не обращается к исходной БД. Точные имена полей и включённость границ бери из версии формата, не придумывай.
- Заполнение окна и нехватка диска приводят к предусмотренной паузе с сохранением возможности продолжить; незавершённые результаты не удаляются автоматически.

При изменении сопоставления товаров проверяй подтверждённый бренд и точный MPN/алиас, происхождение полей и запрет изображений Olnisa. Для очистки проверяй отдельное действие пользователя и принадлежность подтверждения нужной партии/копии.

Докажи затронутые свойства тестами на временных данных, включая повтор после сбоя. Не подключай ещё не реализованные этапы в обход принятого плана. Этот скилл не даёт разрешения на удаление рабочих данных или изменение Selectel.
