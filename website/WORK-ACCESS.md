# Как подключиться с работы и работать с сайтом

Инструкция для Windows и PowerShell. Сведения о проекте сверены с документацией репозитория 24 ноября 2026 года; подключение с рабочего компьютера нужно проверить на месте.

## 1. Подготовь рабочий компьютер

Нужны Git, клиент OpenSSH и, для редактирования серверных файлов, VS Code с расширением Remote - SSH. Проверь в PowerShell:

```powershell
git --version
ssh -V
```

Если команда не найдена, установи Git for Windows или компонент Windows «Клиент OpenSSH» в рамках правил рабочего компьютера. Пароли сайта, сервера и GitHub в эту инструкцию не записываются.

## 2. Создай отдельный ключ для рабочего компьютера

На домашнем компьютере доступ ранее работал через `~/.ssh/id_ed25519`. На рабочем компьютере создай свой ключ. Сначала проверь, свободно ли имя:

```powershell
Test-Path "$env:USERPROFILE\.ssh\id_ed25519_energostor_work"
```

Если результат `False`, создай ключ и задай парольную фразу:

```powershell
ssh-keygen -t ed25519 -f "$env:USERPROFILE\.ssh\id_ed25519_energostor_work" -C "energostor-work"
```

Если результат `True`, используй существующий ключ или выбери другое имя; не перезаписывай его. Покажи публичную часть:

```powershell
Get-Content "$env:USERPROFILE\.ssh\id_ed25519_energostor_work.pub"
```

Передать на сервер нужно только одну строку из файла `.pub`. Файл без `.pub` — закрытый ключ: оставь его на рабочем компьютере и не добавляй в GitHub.

С компьютера, где доступ уже работает, подключись к серверу:

```powershell
ssh root@136.234.4.214
```

В серверной оболочке выполни:

```bash
install -d -m 700 /root/.ssh
touch /root/.ssh/authorized_keys
chmod 600 /root/.ssh/authorized_keys
nano /root/.ssh/authorized_keys
```

Добавь публичный ключ рабочего компьютера отдельной строкой, сохрани файл: Ctrl+O, Enter, Ctrl+X. Существующие строки оставь. Держи это подключение открытым, пока не проверишь вход с работы. Если доступа нет ни с одного компьютера, потребуется консоль сервера в личном кабинете Selectel.

## 3. Подключись с работы

В PowerShell рабочего компьютера:

```powershell
Test-NetConnection 136.234.4.214 -Port 22
ssh -o IdentitiesOnly=yes -i "$env:USERPROFILE\.ssh\id_ed25519_energostor_work" root@136.234.4.214
```

При первом входе SSH предложит подтвердить ключ сервера. Сравни отпечаток с результатом команды, выполненной через уже доверенное подключение или консоль Selectel:

```bash
ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
```

Подтверждай вход при совпадении отпечатков. После входа проверь сервер и папку:

```bash
hostname
ls -ld /opt/energostor-next/upload
cd /opt/energostor-next
pwd
```

Ранее зафиксированное имя сервера — `energostor-dev`. Команда `exit` завершает SSH-сеанс.

Для удобства добавь в файл `%USERPROFILE%\.ssh\config` следующий блок, сохранив остальные настройки:

```sshconfig
Host energostor-work
    HostName 136.234.4.214
    User root
    IdentityFile ~/.ssh/id_ed25519_energostor_work
    IdentitiesOnly yes
```

Теперь вход выполняется командой `ssh energostor-work`. В VS Code выбери Remote-SSH: Connect to Host → `energostor-work`, затем открой `/opt/energostor-next`. Правки в этом окне сразу меняют серверные файлы, поэтому сначала сохрани резервную копию нужных файлов.

## 4. Скачай исходники с GitHub

Выполняй на рабочем компьютере, в папке для проектов:

```powershell
git clone --branch website --single-branch https://github.com/starosvetsky/ESPBS.git ESPBS-website
cd ESPBS-website
git status
git pull --ff-only
```

Если проект уже скачан, перейди в его папку, проверь `git status`, ветку командой `git branch --show-current` и выполни `git pull --ff-only`. При незавершённых правках или конфликте сначала разбери их, чтобы сохранить работу с другого компьютера.

Доступ к GitHub и SSH-доступ к Selectel настраиваются отдельно. Для закрытого репозитория или отправки изменений Git может запросить вход в GitHub через браузер.

После правок проверь diff и добавь только нужные файлы:

```powershell
git diff
git add website/WORK-ACCESS.md
git commit -m "Update server access instructions"
git push origin website
```

Это пример для изменения инструкции. Для работы с сайтом укажи в `git add` свои изменённые файлы и напиши сообщение о фактической правке. Базы, архивы, пароли, закрытые ключи и серверные конфигурации с секретами в Git не добавляй.

## 5. Как публиковать изменения сайта

`git push` сохраняет исходники на GitHub. Автоматический деплой ветки `website` не настроен. Для публикации нужно отдельно проверить сервер, сохранить резервную копию изменяемых файлов и перенести нужные изменения в текущую установку.

Перед публикацией прочитай [описание текущего OpenCart](opencart/migration/README.md), [правила оформления](opencart/migration/UI.md) и, если работаешь с новостями, [инструкцию редактора](opencart/migration/EDITORIAL.md). Не копируй весь репозиторий поверх работающего сайта.

Общий редизайн отменён 23 ноября 2026 года. Для восстановления согласованного оформления предусмотрен `restore-design.py`; старый `install-ui.py` повторно не запускай. `import-release.py` пересоздаёт данные витрины и не подходит для обычной публикации правок поверх рабочей базы.

## Если подключение не работает

- **`TcpTestSucceeded: False` или тайм-аут.** Проверь адрес и доступность порта 22 из рабочей сети. Ранее SSH мешал туннель SOTA: помогло исключение `ssh.exe` из туннеля. Если доступ ограничен рабочей сетью, обратись к её администратору.
- **`Permission denied (publickey)`.** Проверь путь после `-i`, наличие соответствующего публичного ключа в `/root/.ssh/authorized_keys` и пользователя `root`. Парольная фраза ключа — та, которую ты задал при его создании.
- **`REMOTE HOST IDENTIFICATION HAS CHANGED`.** Сначала выясни причину через консоль Selectel и проверь отпечаток. Не удаляй запись из `known_hosts` без проверки.
- **Сайт запрашивает логин и пароль.** Авторизация предпросмотра в браузере отличается от входа по SSH. Пароли в репозитории не хранятся.
- **Изменения появились на GitHub, но не на сайте.** После push нужен отдельный деплой; порядок зависит от изменённых файлов.
