# Общий каталог Энергостора

Витрина **всех сохранённых парсером товаров** вместо страницы одного бренда:
двухуровневая рубрикация, поиск, фильтры, отдельная страница «По брендам» и
переиспользуемое меню для основного сайта.

Комплект автономный: Python 3.12 (только стандартная библиотека) + buildless
HTML/CSS/JS. Координатор подключает API и статику к сайту, ничего в этой папке
для этого менять не нужно.

```
build_catalog.py            сборка производной БД из партий парсера (read-only)
server.py                   HTTP API (ThreadingHTTPServer, loopback)
espbs_catalog/
  taxonomy.py               13 разделов / 91 подраздел; правила для 505 путей
  textproc.py               очистка описаний, ссылок, идентификаторов
  store.py                  схема, потоковая сборка, дедупликация, атомарная замена
  data.py                   встроенные данные (505 путей аудита)
  data/source_paths.json    пути категорий и их счётчики из аудита
frontend/
  catalog/index.html        общий каталог          → /energostor/catalog/
  brands/index.html         «По брендам»           → /energostor/brands/
  assets/catalog/           общие ресурсы          → /energostor/assets/catalog/
    catalog.css  config.js  api.js  menu.js  catalog-page.js  brands-page.js
tests/                      unittest (96 тестов)
tools/                      вспомогательные скрипты (демо-данные, проверка рубрикации)
```

## Быстрый старт

```bash
# 1. Собрать витрину из сохранённых партий (источник открывается только на чтение)
python build_catalog.py --source /var/lib/espbs --dest data/catalog.sqlite3

# 2. Поднять API на loopback
python server.py --db data/catalog.sqlite3 --host 127.0.0.1 --port 8766

# 3. Проверить
curl -s http://127.0.0.1:8766/health
curl -s "http://127.0.0.1:8766/api/meta" | head -c 400
```

Локальный просмотр фронтенда (демо-данные, 42 товара):

```bash
python tools/demo_data.py
python server.py --db data/catalog.sqlite3 --port 8766 --web-root frontend
# http://127.0.0.1:8766/catalog/ и http://127.0.0.1:8766/brands/
```

`--web-root` — только для разработки: в бою статику раздаёт nginx, а сервис
отвечает лишь на API. На Windows файл БД нельзя заменить, пока сервис держит
его открытым: остановите сервис на время пересборки (на Linux `os.replace`
работает даже с открытым файлом).

## Сборка

```
python build_catalog.py --source <каталог данных парсера> --dest <файл.sqlite3>
                        [--limit N] [--max-mb 2048] [--quiet]
```

* Источник — каталог с `batches/*.sqlite3` (или отдельный файл партии). Каждая
  партия открывается как `file:...?mode=ro`, читается курсором построчно;
  payload разбирается по одной записи, каталог целиком в память не попадает.
* Запись идёт в `.catalog.sqlite3.<pid>.tmp` рядом с целью. Целевой файл
  заменяется через `os.replace` **только** после успешной сборки и `ANALYZE`.
  Любая ошибка — временный файл удаляется, прежняя БД остаётся нетронутой.
* `--max-mb` — предохранитель по размеру: при превышении сборка падает и не
  публикует результат (диск на сервере ограничен).
* Данные парсера не изменяются: ни `UPDATE`, ни файловых операций по источнику.

Итоговые метаданные (`meta`): `raw_records`, `unique_products`, `duplicates`,
`skipped`, `batches`, `products_with_images/documents/attrs`,
`first_collected`, `last_collected`, `built_at`, `schema_version`.

## Дедупликация

Слияние только по подтверждённому бренду **и** точному MPN:

* ключ — `brand|mpn`, нормализованные по пробелам и регистру (без удаления
  дефисов и цифр), MPN из `mpn`; при пустом `mpn` запись не сливается ни с чем;
* без бренда или без MPN каждая запись остаётся отдельным товаром;
* одинаковый MPN у разных брендов — разные товары;
* при совпадении ключа побеждает **более новый снимок** (`collected_at`);
  старый или равный по времени не перезаписывает данные;
* поля, которых в новом снимке нет (описание, характеристики, фото, документы),
  переносятся из предыдущего — это перенос собранных данных, не выдумывание;
* `id` товара стабилен между сборками: `sha1(key)` для товаров с MPN,
  `sha1(record_id)` для остальных;
* внутренняя таблица `audit_records` (record_id → product_id, источник,
  outcome) остаётся в производной БД для разбора, но в API не отдаётся.

## Рубрикация

13 родительских разделов и 91 подраздел — по фактическому ассортименту, а не
по 16 пунктам старого мегаменю. Все 505 путей из аудита получают конкретный
подраздел; проверка зафиксирована тестом.

| Раздел | Примеры подразделов |
|---|---|
| Низковольтное оборудование | автоматические выключатели, УЗО и дифавтоматы, контакторы, реле, клеммы |
| Шкафы, щиты и корпуса | шкафы, распределительные щиты, IT-шкафы, комплектующие |
| Промышленная автоматизация | ПЛК, модули ввода-вывода, панели оператора, датчики |
| Приводы и двигатели | электродвигатели, частотные преобразователи, сервоприводы |
| Питание и защита | ИБП, блоки питания, УЗИП, заземление, компенсация |
| Измерительные приборы и учёт | КИП, счётчики, трансформаторы тока |
| Кабельные системы и монтаж | лотки, наконечники, кабельные вводы, хомуты |
| Электроустановочные изделия | розетки, выключатели, рамки, механизмы |
| Освещение | светильники, лампы, аварийное освещение |
| Сетевое и телекоммуникационное оборудование | коммутаторы, маршрутизаторы, Wi-Fi, видеонаблюдение |
| Электронные компоненты | микросхемы, транзисторы, конденсаторы |
| Инструмент, крепёж и расходники | ручной инструмент, сварка, крепёж, химия |
| Прочее оборудование | без уточнённой рубрики, устаревшее |

Правила — `espbs_catalog/taxonomy.py`:

* `RULES` — упорядоченный список регулярных выражений по пути источника
  (первое совпадение выигрывает; короткие основы вроде `shhit` заякорены,
  чтобы не ловить `zashhita`);
* `OVERRIDES` — точные пути, которые ключевые слова ставят не туда;
* запись без категории (`(no-source-category)`) проходит `classify_unbranded`:
  проверяемые правила по префиксу модели и словам в описании для D-Link
  (`DES/DGS/DXS` → коммутаторы, `DIR/DWR` → маршрутизаторы, `DAP/DWL` → Wi-Fi,
  `DCS/DNR` → видеонаблюдение, `DPH` → IP-телефония и т. д.) и Eltex
  (`MES`, `ESR`, `WEP`, `TAU`…), резерв — «Прочее сетевое оборудование»;
  любой другой бренд — «Прочее оборудование»;
* ничего не отбрасывается: неизвестный путь попадает в «Прочее оборудование».

Проверить покрытие и распределение:

```bash
python tools/check_taxonomy.py            # всё дерево с количеством записей
python tools/check_taxonomy.py low-voltage cable
```

## Публичные данные

| Отдаём | Не отдаём |
|---|---|
| название, бренд, артикул, раздел, описание, характеристики, фото, документы | `source`, `source_url`, `external_id`, `record_id`, `provenance`, `enrichment`, партия, парсер, IP |
| строку «Цена по запросу» | цену стороннего продавца, наличие |

* Описание чистится от рекламного хвоста («… артикул товара … Купите … в
  компании …»), телефонов, почты, адресов сайтов и цен; технические
  предложения сохраняются. Если после чистки смысла не осталось — пустая
  строка, а не выдуманный текст.
* Фото и документы — только абсолютные `http(s)` без credentials. Изображения
  с домена-источника и его поддоменов отбрасываются, `javascript:`/`data:` —
  тоже; `enrichment` не читается как источник картинок.
* Все строки уходят как обычный текст; фронтенд вставляет их через
  `textContent`, не через `innerHTML`.
* Пустые фото/характеристики не подменяются заглушками-выдумками: API отдаёт
  пустой список, интерфейс честно пишет «Фото нет».

## API

Сервис слушает `127.0.0.1:8766`, отвечает JSON, допускает префиксы
`/energostor/api/catalog`, `/api/catalog`, `/api` — поэтому работает и при
проксировании, и напрямую.

### `GET /health`

```json
{"status":"ok","products":49612,"schema":"3","built_at":"2026-11-01T08:00:00Z"}
```

### `GET /api/meta`

```json
{
  "stats": {"products": 49612, "raw_records": 49612, "duplicates": 0, "brands": 312,
            "categories": 91, "with_images": 861, "with_documents": 57,
            "with_attributes": 1905, "first_collected": "…", "last_collected": "…",
            "built_at": "…", "source_batches": 3},
  "categories": [
    {"slug": "low-voltage", "title": "Низковольтное оборудование", "count": 23596,
     "children": [{"slug": "lv-breakers", "title": "Автоматические выключатели", "count": 3372}]}
  ],
  "brands": [{"slug": "schneider-electric", "title": "Schneider Electric", "count": 12034}]
}
```

Пустые разделы и бренды в ответ не попадают — меню строится только по тому,
что реально есть в каталоге.

### `GET /api/products`

Параметры: `q` (≤120 символов, до 6 слов, регистронезависимо для кириллицы),
`brand` (slug), `category` (slug родителя или подраздела), `page` (≥1, ≤5000),
`limit` (1…60, по умолчанию 24), `sort` (`name` | `brand` | `new`).

```json
{
  "items": [{
    "id": "4f2a9c1d8e7b6a50", "name": "Выключатель автоматический 3P 63 А",
    "brand": "Schneider Electric", "brandSlug": "schneider-electric",
    "mpn": "A9F04363", "parent": "low-voltage",
    "parentTitle": "Низковольтное оборудование", "child": "lv-breakers",
    "childTitle": "Автоматические выключатели", "summary": "…",
    "image": "https://…/photo.jpg", "hasDocs": true, "hasAttrs": true,
    "price": "Цена по запросу"
  }],
  "total": 3372, "page": 1, "pages": 141, "limit": 24,
  "query": "", "brand": "", "category": "lv-breakers", "sort": "name"
}
```

Фильтрация и пагинация выполняются в SQL по индексированным колонкам
(`parent`, `child`, `brand_slug`), поиск — по заранее подготовленной
lowercase-колонке `search` с экранированием `%`/`_`; payload при запросах не
разбирается. Неизвестный бренд или раздел даёт пустую выдачу, а не ошибку.

### `GET /api/products/{id}`

```json
{
  "id": "…", "name": "…", "brand": "…", "brandSlug": "…", "mpn": "…",
  "parent": "…", "parentTitle": "…", "child": "…", "childTitle": "…",
  "summary": "…", "description": "…",
  "attributes": [{"label": "Номинальный ток", "value": "63 А"}],
  "images": ["https://…/1.jpg"],
  "documents": [{"name": "Паспорт", "url": "https://…/passport.pdf"}],
  "price": "Цена по запросу", "updated": "2026-03-01T10:00:00Z"
}
```

Ошибки: `400` — некорректный id/параметры, `404` — нет товара или маршрута,
`405` — не POST/GET. Тело: `{"error": "…"}`. Заголовки: `X-Content-Type-Options:
nosniff`, `Referrer-Policy: no-referrer`, CORS `*` для GET/OPTIONS.

## Фронтенд

* `/energostor/catalog/` — поиск, дерево разделов (родитель → подраздел),
  бренды, сортировка, пагинация, карточка в диалоге с характеристиками,
  документами, фото и `mailto`-запросом. Состояние хранится в URL (`q`, `brand`,
  `category`, `sort`, `page`), работает «назад/вперёд».
* `/energostor/brands/` — бренды из метаданных с алфавитным указателем и
  поиском; клик ведёт в каталог с фильтром `brand`.
* Состояния: скелетоны при загрузке, пустая выдача с кнопкой сброса, ошибка с
  повтором. Устаревшие ответы отбрасываются: каждый запрос получает номер, а
  `AbortController` отменяет предыдущий.
* Адаптив 390/768/1440: на мобильном фильтры сворачиваются в кнопку, сетка
  карточек 3 → 2 → 1, длинные меню прокручиваются.
* Подключение API: `assets/catalog/config.js` (`apiBase: 'auto'` — на сайте
  `/energostor/api/catalog`, локально `http://127.0.0.1:8766`).

### Меню для основного сайта

`assets/catalog/menu.js` строит двухуровневое меню из `/api/meta` и вход
«По брендам». Подключение к существующей шапке (сами файлы сайта не меняются):

```html
<link rel="stylesheet" href="/energostor/assets/catalog/catalog.css">
<script src="/energostor/assets/catalog/config.js" defer></script>
<script src="/energostor/assets/catalog/api.js" defer></script>
<script src="/energostor/assets/catalog/menu.js" defer></script>

<!-- в нужном месте шапки -->
<div data-catalog-menu></div>
```

Или вручную: `CatalogMenu.mount(document.querySelector('#my-menu'))`.
Меню доступно с клавиатуры: `Enter`/`Space` открывает, `↓` переводит фокус в
первый пункт, `Esc` закрывает и возвращает фокус на кнопку; клик вне панели
закрывает её.

## Деплой

```ini
# /etc/systemd/system/energostor-catalog.service
[Unit]
Description=EnergoStor catalog API
After=network.target

[Service]
User=www-data
WorkingDirectory=/srv/energostor-catalog
ExecStart=/usr/bin/python3 server.py --db /var/lib/energostor-catalog/catalog.sqlite3 --port 8766
Restart=on-failure
NoNewPrivileges=yes
PrivateTmp=yes

[Install]
WantedBy=multi-user.target
```

```nginx
location /energostor/api/catalog/ {
    proxy_pass http://127.0.0.1:8766/;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_read_timeout 30s;
    add_header Cache-Control "public, max-age=15";
}
```

Пересборка (по cron/таймеру): собрать в новый файл, затем
`systemctl restart energostor-catalog`. Сборка атомарна, но сервис держит
соединение со старой БД — после подмены нужен рестарт (или перезапуск по
`SIGHUP`, если добавите обработчик).

## Тесты


Покрыто (96 тестов, синтетические данные — серверные не использовались):

* дедупликация по бренду+MPN, сохранение записей без MPN, порядок снимков,
  стабильность id, перенос отсутствующих полей;
* категории: все 505 путей, границы слов (`zashhita` ≠ `shhit`), правила
  D-Link/Eltex, «Прочее» только для мусорных путей, счётчики родителей;
* фильтры, кириллический поиск без учёта регистра, экранирование `%`/`_`,
  пагинация и клампы `limit`, сортировки, 404/400, префиксы прокси;
* защита от утечек: в ответах нет `source`/`source_url`/`provenance`/партии,
  картинки с домена-источника вырезаны, `javascript:`/`data:` отклонены,

* атомарность: ошибка в середине сборки и битая партия оставляют прежнюю БД,
  временный файл удаляется; источник не меняется;
* очистка описаний: уходит реклама, телефоны, почта, цены; остаются
  характеристики;
* фронтенд: `node --check` для всех JS, ссылки на ресурсы, отсутствие
  упоминаний источника и небезопасных DOM-вставок.

## Ограничения

* **Проверка на реальных данных не выполнялась.** Здесь синтетические партии;
  размеры реального каталога (≈49 600 записей, 505 путей) взяты из аудита, но
  фактическая сборка на сервере — шаг координатора.
* 8 281 запись без исходной категории рубрицируется правилами по бренду и
  модели; всё, что не опознано уверенно, остаётся в «Прочее оборудование» —
  это осознанное решение, а не потеря данных.
* Фотографий в сохранённых данных мало (по аудиту `images` пусты у ~48 771
  записи), поэтому у большинства карточек будет «Фото нет».
* Цены не публикуются: у всех товаров «Цена по запросу», запрос уходит письмом.
* Дедупликация намеренно консервативная: похожие названия без MPN не
  сливаются, поэтому часть дублей останется (это лучше ложного слияния).
* На Windows замена открытой БД невозможна — нужен останов сервиса.
* Статический фронтенд рассчитан на размещение рядом с сайтом; страницы
  помечены `noindex` до решения о публикации.
