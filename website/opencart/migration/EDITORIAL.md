# Новости и практика Энергостора

Источник редакционных данных — `website/editorial/articles.json`. Контент
публикуется в информационные страницы OpenCart, лента доступна на `/news`.
После восстановления дизайна 23.11.2026 главная не изменяется: материалы
публикуются только в самостоятельном разделе `/news`. Не добавлять стили
новостей в общую шапку и не запускать отменённый `install-ui.py`.
Существующие URL `/tpost/`
сохранены; четыре старых материала переписаны и снабжены датой обновления.
Цель ежедневного выпуска — десять новых материалов, а не десять обновлений
даты старых текстов. Первый выпуск: девять новостей производителей и один
практический материал. Тексты основаны на первоисточниках, ссылки внутри статей.

## Как готовить выпуск

1. Просмотреть опубликованный JSON и последние выпуски: не повторять тему под
   новым заголовком. Искать полезные обновления разных производителей и
   разделов: аппаратура, корпуса, приводы, питание, автоматика, измерение,
   освещение, кабельные и сетевые системы.
2. Читать конкретные оригинальные сообщения производителей, документацию и
   публикации регуляторов. Поисковый сниппет не заменяет проверку первоисточника.
   Даты публикации на Энергосторе и исходного события не смешивать.
3. Писать своими словами: что произошло, для кого это имеет значение и что
   проверить в проекте. Содержательная короткая заметка лучше общего текста
   о «динамично развивающемся рынке». Избегать одинаковых вводных и повторов.
   Соблюдать ограничения цитирования и объём использования источников.
4. `kind: Новость` требует подтверждённой даты `event_date`. Для материалов
   без нового события использовать `kind: Практика`. Не создавать новости
   из предположений и не выдумывать результаты исследований ради числа 10.
   При нехватке событий дополнять выпуск самостоятельными полезными разборами.
   Если десять качественных материалов подготовить не удалось, прямо сообщить
   фактическое количество и причину.
5. Сохранять `slug`, заголовок до 64 символов (ограничение OpenCart), краткое
   описание, тип, тему, дату публикации, абзацы и прямые HTTPS-ссылки на источники.
   У существующих записей сохранять исходную дату, для исправлений добавлять
   `updated`. Не пересоздавать весь JSON из десяти последних записей.
6. Не упоминать Merlion, не включать цены и рекламные утверждения о наличии,
   дилерстве или заказчиках Энергостора. Не копировать фотографии из новостей
   без подтверждённых прав. Отделять сведения производителя от выводов автора.
7. Для Дзена готовить один самостоятельный текст по лучшей теме выпуска,
   с источниками и ссылкой на соответствующий материал сайта. Сохранять в
   `website/editorial/dzen/`. Пока канала нет: только черновики. Не создавать
   аккаунт, не принимать условия и не заявлять публикацию без доступа.

## Установка и проверка

Перед правками выполнить git status и fetch. Проверить, что чужие изменения
не будут перезаписаны. Деплой публикаций на energostor.ru разрешён владельцем.
Не пересобирать товарную базу, не трогать парсер и заказы.

```sh
scp website/editorial/articles.json root@136.234.4.214:/opt/energostor-next/articles.json
python3 /opt/energostor-next/install-editorial.py /opt/energostor-next /opt/energostor-next/articles.json
```

Последняя команда выполняется на сервере по SSH. При изменении установщика
копировать также `install-editorial.py`, `news.php`, `news.twig`, `editorial.css`
из этого каталога в `/opt/energostor-next/`. Установщик сохраняет копии таблиц
информационных страниц и изменяемых файлов вне webroot в `editorial-backups`.
Он не меняет товарные таблицы. Не удалять резервные копии автоматически.
При существенном росте выпуска отдельно оценить объём накопленных копий и
согласовать их хранение; диск сервера ограничен.

После установки проверить HTTP 200 всех новых и обновлённых статей, одну
каноническую ссылку, содержание и источники, главную, `/news`, стили и карту
`/sitemap-news.xml`. Лента имеет серверную пагинацию по 20 материалов.
Старая Bootstrap-шапка конфликтовала с `display:contents`; совместимость
исправлена в `editorial.css`. Визуально проверять внутренние страницы и главную.
Повторная установка темы требует повторной установки юридических страниц и
редакционного раздела. После проверок — целевой commit и push в ветку website.
