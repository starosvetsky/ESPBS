# Проба Scrapling — 2 ноября 2026

Эксперимент полностью отделён от рабочего парсера: отдельная копия репозитория,
собственное окружение, зависимости только в experiments/requirements-scrapling.txt.
В espbs/, серверных requirements, CI и настройках Selectel изменений нет.

## Что проверено

Одна живая страница https://vad.merlion.ru/ получена существующим Client ESPBS
с проверкой robots.txt. Одинаковый HTML передан двум независимым процессам:
BeautifulSoup и Scrapling 0.5. Правило: `.block-vendors a[href]`, только профили
первого уровня /vendors-and-solutions/ на том же домене, с названием и логотипом.
Дубли объединены по профилю, конфликтующие данные отклоняются.

Автоматическое распознавание текущего Adapter вернуло «структура не распознана».
С явным правилом оба извлекателя дали одинаковые 190 записей, каждая с name,
profile_url, logo_url. Это вендоры, не товарные карточки. Старый XML из 18 вендоров
был выбранной частью каталога; эти числа относятся к разным выборкам.
Содержимое логотипов не скачивалось: проверено наличие ссылок в HTML.

Один локальный замер Windows / Python 3.13, включая импорт библиотеки:

| Способ | Извлечение, секунды | Пиковая память процесса |
| --- | ---: | ---: |
| BeautifulSoup | 0,308 | 31,05 МиБ |
| Scrapling | 0,114 | 30,87 МиБ |

Получение HTML заняло 5,89 с, включая robots и задержку клиента. Время сети общее,
поэтому оно не включено в сравнение извлекателей. Замер один, не полноценный
бенчмарк; он не доказывает ускорение других сайтов. Качество проверено сравнением
всех полей двух результатов, не независимой ручной сверкой каждого бренда.

JavaScript и браузерный режим НЕ проверялись. На этой странице данные уже в HTML,
так что ошибка распознавания сама по себе не доказывает необходимость браузера.
Scrapling не определил поля автоматически: селектор задали явно. Здесь библиотека
пока не даёт функциональности, которой нельзя достичь существующим BeautifulSoup.

## Повтор пробы

Из отдельной копии проекта (не из окружения рабочего сервиса):

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r experiments/requirements-scrapling.txt
.\.venv\Scripts\python.exe experiments/scrapling_trial.py
.\.venv\Scripts\python.exe -m unittest discover -s experiments -p test_scrapling_trial.py -v
```

Только первый запуск обращается к сайту. Тесты синтетические, без сети: фильтрация
чужих ссылок и навигации, обязательные поля, дубли и конфликтующие карточки — прошли.
HTML, список и машинный отчёт остаются в игнорируемом data/scrapling-trial/.
Рабочие БД, задания и настройки не читаются и не изменяются. Произвольный URL
скрипт не принимает. На Linux память указывается как RSS в конце процесса, а не
пик; поле memory_method явно различает эти измерения.

## Решение

Подключение к рабочему парсеру пока не оправдано этой пробой. Код пробы сохранён
для воспроизведения. Отдельный следующий опыт — браузерный режим на согласованном
источнике, где нужные данные действительно появляются только после JavaScript,
с учётом robots, всех дополнительных запросов, памяти и времени браузера.
Установка Scrapling на Selectel и замена текущего сборщика не выполнялись.
