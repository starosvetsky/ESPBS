# Правила ESPBS / EnergoStor

- Парсер выполняется на Selectel. Диск ограничен. Пользователь вручную скачивает партии архивами на компьютер, затем отдельно подтверждает освобождение серверного места.
- Формат первого этапа: ZIP с XML и манифестом. Будущий импорт в EnergoStore/OpenCart разрабатывается отдельно; совместимость с ним пока не заявлять.
- Компьютер не обязан быть постоянно включён. Не заменять этот сценарий автоматической синхронизацией с основной локальной БД.
- Сохранилась только неполная версия v0.5. Пользователь разрешил разработать отсутствующие компоненты; дополнительных файлов не ждать.
- Не удалять результаты из-за ошибки, переполнения диска, отправки HTTP-ответа или начала скачивания. Очистка относится только к проверенной партии и требует отдельного действия пользователя.
- Обрабатывать каталог порциями. Не хранить весь каталог в памяти. Сохранять исходные поля и происхождение данных.
- Автоматическое объединение товаров: только подтверждённый бренд + точный MPN или подтверждённый алиас. Изображения Olnisa запрещены.
- Не обходить ограничения источников. Реальные адреса и корректность извлечения проверять; тестовые данные явно отличать от реального сбора.
- Перед работой проверять локальные изменения и получать актуальное состояние origin. Не перезаписывать чужие изменения.
- После завершённого шага выполнить относящиеся к нему проверки, обновить документацию, сделать коммит и push. Пользователь разрешил это для работы с нескольких компьютеров.
- Не включать в Git БД, архивы, выгрузки, журналы и секреты. GitHub Pages публикует только явно выбранные файлы страницы.
- Не менять сервер без доступного подключения и проверки его состояния. Локальные проверки не доказывают развёртывание на Selectel.

План: `docs/PLAN.md`. Сценарии: `docs/UX_FLOW.md`.

## Скиллы и независимая проверка

Комплект разработки и передача между задачами: `docs/agent-kit/HANDOFF.md`.
Используй относящиеся к задаче скиллы из `.agents/skills/`.
Для существенных изменений хранения, восстановления и экспорта делегируй
независимую проверку `espbs-qa` или `espbs-reviewer`, если субагенты доступны.
Роли находятся в `.codex/agents/`; способ работы без автоматического обнаружения
описан в HANDOFF.md. Простые правки не требуют запуска команды агентов.
По умолчанию код меняет один исполнитель; координатор объединяет результаты,
проверяет их и выполняет commit/push. Эти инструкции не разрешают деплой
или очистку рабочих данных и не заменяют согласованный план.
